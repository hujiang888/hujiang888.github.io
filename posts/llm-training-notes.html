把大模型训练拆成五步：我的课程实验笔记

一开始我以为“训练大模型”是一件事，真正跑完课程实验才发现，它更像五件相互依赖的事： 分词、注意力、预训练、SFT、LoRA。每一步都有独立的坑，也都能单独验证。

01 · 分词器：先把文字变成数字

实验从一个约 6400 词表的 BPE 分词器开始。BPE 的核心很朴素：从字符开始，反复统计相邻字符对， 把出现频率最高的一对合并成新的 token，直到达到目标词表大小。

我用两套脚本做了对比：一套是工程版，产出 tokenizer.json；另一套是从零手写的最小实现， 用来确认自己真的理解合并过程。手写版一开始在边界判断上出错，最后一个字符会丢，修正循环边界后才做到编解码一致。 

# 语料很大时，不要一次性读入
max_line_num = 10000
# 先限制样本量，跑通流程，再扩大规模

这一步最容易忽略的是 PAD / UNK。分词器没有配置填充位时，取 id 可能返回空值，后面拼 batch 就会报类型错误。

02 · 注意力：让模型知道该看哪里

缩放点积注意力的公式很短，但实现里有几个细节：QKV 的维度、除以 sqrt(d_k)、 因果掩码，以及 softmax 的数值稳定性。手写 naive softmax 时，分数一大就溢出；改用 F.softmax 并做缩放后才稳定。

因果掩码的作用是防止模型看到未来的 token。我一开始用 0/1 相乘再按行归一化，结果注意力权重算错了； 正确做法是先用 tril 生成下三角掩码，把上三角填成负无穷，再做 softmax。

课程里还对比了 MHA、MQA、GQA 和 Flash Attention 的思路。它们优化的是同一个问题： 在长序列下，怎样减少显存访问与计算量。理解这一点，比记住某个 API 更重要。

03 · 预训练：让模型学会预测下一个词

预训练阶段的目标是 Next Token Prediction：给定前文，预测下一个 token，损失用交叉熵。 数据来自课程提供的 jsonl 语料，我把 DATA_PATH 指向实际文件，并先限制读取一万行， 避免 1.2G 数据一次性加载导致内存溢出。

第一轮只跑 1 个 epoch，确认 loss 能正常下降并保存 pretrain_768.pth。 loss 有震荡不一定是代码错，样本难度差异、padding 参与计算都会造成波动； 判断标准是整体趋势是否向下，而不是某一步的绝对值。

本机没有显卡，CPU 训练很慢。我的策略是缩小模型与数据量先跑通流程， 把完整训练放到有显卡的环境；这比在本地死等更有效。

04 · SFT：教模型按对话格式回答

SFT 的关键不是“再训一遍”，而是构造对话格式与 loss mask。我把数据整理成 ChatML 风格的 user / assistant 结构，只对 assistant 的回复计算损失，避免模型把用户问题也背下来。

一开始 loss mask 错位，模型只学了回复的后半段，loss 降不下去。核对 assistant 起止位置与标签偏移后， 训练才恢复正常。课程实验里，SFT 后的 loss 大约从 2.0 降到 1.7——数字不惊艳，但趋势是对的。

05 · LoRA：用很小的旁路改动模型

LoRA 的思路是冻结原模型，只在部分线性层旁注入低秩矩阵：A 用高斯初始化， B 初始化为零，训练时只更新这两个小矩阵。课程里取 r=8， 单个 LoRA 权重只有几百 KB。

我用同一份底座分别训了身份 LoRA 和医疗问答 LoRA。加载时按模块名匹配 lora. 前缀， 否则权重不会生效；医疗数据训练轮数过多时，模型开始遗忘旧知识，最后通过减少轮数并按验证集挑选权重解决。

小模型的容量有限，微调数据的风格会直接影响输出。数据质量比“多训几轮”更重要。

最后：把每一步跑通

这次实验最大的收获，不是某一个 loss 数字，而是建立了一条可以复现的链路： 分词器 → 注意力 → 预训练 → SFT → LoRA。每一步都能单独测试，也能单独替换。

如果重新做一遍，我会更早写单元测试：分词器的编解码一致性、注意力的掩码形状、loss mask 的边界， 这些都值得用一个小测试守住。模型训练看起来是“跑起来就行”，真正省时间的却是这些不起眼的检查。

写于 2026 年 10 月，课程实验完成之后。
